# Agent guide

## What this repo does

This is a Path of Exile **1** item-filter builder, focused on leveling filters. The Vue app edits filter configurations; the TypeScript compiler turns them into PoE `.filter` text; export writes the filter and its custom sound pack to the user's game folder. Start with `README.md` for setup and user-facing workflows. Do not confuse this with PoE 2 filter syntax or assume current item bases/league mechanics from memory.

## Where to look

- `frontend/src/`: Vue editor, live preview, settings and sound controls; `frontend/src/api.ts` calls the server.
- `src/server/app.ts`: Express API for filter lifecycle, config, preview, export, settings and sounds.
- `src/config/`: filter lifecycle, form schema (`form-schema.ts`), reference data, settings and user override storage.
- `src/filters/template/`: example TypeScript config and standard `index.ts` entry point; individual filters live under `src/filters/<name>/`.
- `src/filters/shared/config-loader.ts`: JSON serialization/deserialization and config loading. `config.json` is the UI-owned source of truth when present; `config.ts` is a supported fallback.
- `src/filters/shared/sections/options.ts`: `BuildProfile`, `BuildSpecificOptions`, highlight and section config types. `src/filters/shared/defaults.ts` and `styles.ts` hold shared defaults/styles; local user overrides are layered on top.
- `src/filters/shared/compile.ts`: canonical section order for standard filters. `src/filters/shared/sections/`: matching rules for currency, gems, equipment, early leveling, etc.; `src/rule.ts` emits PoE filter blocks.
- `src/sounds/manifest.ts`: named TTS sounds (`id` is stable filename, `text` is spoken content); `src/sounds/paths.ts` handles pack paths/version; `src/scripts/` contains export, generation and sync commands.
- `src/assets/BaseTypes.csv`: base-type data used by `src/scripts/generate-types.ts`; `src/types/autogenerated/` and `src/types/sounds/generated-sounds.ts` are generated. `test/` covers compilation, config, server, sounds and output.

## PoE filter concepts that matter here

- A `.filter` consists of ordered `Show`/`Hide` blocks. Conditions (such as `Class`, `BaseType`, `Rarity`, `AreaLevel`, `ItemLevel`, `Sockets` and `LinkedSockets`) select items; actions set presentation (colors, font size, minimap icon, sound). **Order is behavior:** an earlier matching block takes precedence. Keep targeted highlights before broad rarity rules and the final equipment hide; preserve the unknown-item fallback at the end. Check `compile.ts` before moving sections.
- `Class` matches an item class, while `BaseType` matches base names; use exact matching where a substring would catch unrelated bases. `AreaLevel` is the zone's level, `ItemLevel` the item's level, and `DropLevel` a base's minimum drop level; do not interchange them. Sockets, linked sockets and socket colors are different conditions.
- `buildProfile` holds build preferences (weapon phases, armour, socket colors, shields); `buildSpecificOptions` holds section-specific cutoffs/highlights. Weapon phases are ordered, non-overlapping area-level ranges. Each base defaults to a drop-level + 5 cutoff, bounded by the phase's optional end; an end is required before another phase. Old `earlyWeapons` JSON is mapped to a phase on load without rewriting the file. Unset values usually fall back to shared defaults; an empty list or explicit value can intentionally override a default. Confirm the individual section's handling before changing fallback semantics.
- A _highlight_ is a configurable rule group for base types or classes, rarities and optional restrictions/styles/icons/sounds. Its per-rarity icon/sound settings replace the whole-highlight icon/sound when enabled. See `options.ts`, `sections/highlighted-equipment.ts` and `frontend/src/components/HighlightEditor.vue`.
- Custom TTS sounds use a manifest entry or an ad-hoc phrase. A manifest sound's `id` determines its filename, so changing spoken `text` need not break references. Exports reference a versioned sound folder alongside the `.filter` file, not audio embedded in it.
- Game data changes: verify names/classes against `BaseTypes.csv`, generated types and the current rules before adding a base type. For game syntax or mechanics not modeled in the repo, verify against current PoE 1 sources rather than guessing.

## How to work safely

- UI/config changes may cross `options.ts` → `config-loader.ts` → compiler sections → `form-schema.ts` → Vue components/API → tests. Keep serialized JSON, TS fallback and preview/export behavior aligned. A preview compiles without writing a game filter; export writes to the configured PoE directory.
- Prefer changing source data and generators over generated files. Personal filter folders, `settings.json`, `sounds/`, and `src/filters/shared/user-defaults.{json,ts}` / `user-styles.{json,ts}` are local/ignored; don't add them to commits. Treat an existing user's filters/settings/game files as data, not test fixtures.
- Use `npm run check` before completing TypeScript changes (`typecheck`, Vitest and Prettier). For frontend changes also run `npm run frontend:build`. Add or update focused tests in `test/` when changing rule ordering, matching, cutoffs, serialization or API behavior; assert generated `.filter` lines where appropriate.
- `npm run filtertool` starts the app. `npm run export <filter-name>` and `npm run export-all` regenerate types, clean/sync sounds and write files to the configured PoE folder; they can overwrite existing exports. Do not use export as a harmless validation command. `npm run generate-sounds` may generate TTS audio; see `README.md` for setup and sound management.
- Issues and PRDs live in this repo's GitHub Issues; use `gh` when an issue or ticket is relevant. Do not rely on the removed `docs/` agent guides.
