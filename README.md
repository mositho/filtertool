# poe filter tool

Build and export Path of Exile item filters from a local web app, with shared sections and custom TTS sounds.

Built with leveling filters in mind. Contributions are very welcome.

## Prerequisites

- [Node.js](https://nodejs.org/) installed

## Quickstart

1. Install dependencies.

```bash
npm install
```

Types and autogenerated sound-type definitions are regenerated automatically on install. No extra steps needed.

2. Launch the app.

```bash
npm run filtertool
```

This bootstraps a fresh clone (installs dependencies if missing, seeds settings, ensures generated types), starts the server and frontend, and opens the app in your browser.

3. Set your Path of Exile folder.

On first launch a **quickstart** prompt asks for the **PoE Filter Path** (where exported `.filter` files and the sound pack are written). You can also set it later under **Global Settings**. On Windows the default `<Documents>/My Games/Path of Exile` is used automatically.

4. Create a filter from the sidebar, configure it, and click **Export**.

## Using the app

### Sidebar

- **+** creates a filter; each row has **duplicate** (⧉), **rename** (✎) and **delete** (✕) buttons.
- **Global Settings** opens the settings, defaults and styles view.
- **Export All** saves and exports every filter.

### Editing a filter

The filter editor is organized into sections, each matching a section of the compiled `.filter` output:

- **Build profile** — socket colors and armour bases used to pick "good" links, preferred weapons, and shield progression.
- **Early** — early-campaign weapon highlights and area-level cutoffs for sockets and boots.
- **Links** — which linked-socket items are shown and when they play a sound.
- **Equipment** — rarity thresholds (max area level), jewellery and tinctures.
- **Highlights** — extra build-specific item highlights.

Every highlight shares the same editor:

- **Match** — match _anything_, specific _base types_, or _item classes_.
- **Rarities** — which rarities the highlight applies to (defaults to Normal, Magic and Rare).
- **Customize per rarity** (off by default) — when enabled, configure the icon and sound separately per selected rarity.
- **Modules** (add/remove via **+ Add module**) — minimum attack speed, minimum linked sockets, minimum sockets, min/max area level, weapon cutoff, a single icon, and a single sound. The whole-highlight icon/sound modules are replaced by per-rarity styling when "Customize per rarity" is on.
- Highlights can be **duplicated** and **renamed** from their header.

### Preview, save and export

- The right-hand **Output Preview** shows the compiled `.filter` live; focusing a field scrolls the preview to the matching section.
- **Save** persists the filter's `config.json`; **Save + Export** also writes the `.filter` file and syncs the sound pack to your PoE folder.
- **Discard** reverts unsaved changes; **Ctrl/Cmd+Z** and **Ctrl/Cmd+Shift+Z** undo/redo.

### Global settings

- **Settings** — PoE Filter Path and Sounds Folder Name. The **Sounds** subsection holds the TTS **Locale** and **Speed**, plus:
  - **Generate sounds** — regenerate every TTS sound using the current settings and sync to your PoE folder (shows live progress).
  - **Sync sounds** — clean stale files and copy the existing pack to your PoE folder.
- **Defaults** — shared default values used when a filter leaves a field unset.
- **Styles** — colors, sizes and opacity for the built-in style names, with copy/paste and saved styles.

## Editing filters in TypeScript (alternative)

The UI is the recommended workflow, but a hand-written `config.ts` is still supported as a programmer fallback.

1. Copy the [`src/filters/template`](src/filters/template) folder to a new folder under `src/filters/`.

The template's `config.ts` exposes every configurable section with inline examples. The filter layout is already wired up, so you only edit configuration values; `npm run export-all` skips the template itself.

2. Edit your new filter's `config.ts`.

For most standard filters, `config.ts` is the only file you need to touch. `index.ts` usually only needs changes if you want a different section layout or custom logic.

3. Export your filter.

If your filter folder is `src/filters/yourfilter`, run:

```bash
npm run export yourfilter
```

To export every tracked filter under `src/filters/` in one go:

```bash
npm run export-all
```

> **Breaking changes:** When a sound pack update changes the folder name (e.g. `poeft-sounds` → `poeft-sounds-v2`), exporting overwrites your existing `.filter` file which now references the new sound folder. A warning is printed before export if an existing filter file is found. To keep your old filter working alongside the new one:
>
> - Rename the old `.filter` file in your Path of Exile directory, **or**
> - Rename your filter source folder under `src/filters/` (e.g. `yourfilter-v2`) to produce a differently-named filter file.

> **No automatic config migration:** A hand-written `config.ts` that references removed/renamed fields will fail typechecking — recreate the filter through the Web UI or update the field names. The UI's `config.json` is the single source of truth and is not migrated between schema changes either.

## User Overrides

Personal shared defaults or styles for all filters can live in local override files:

- `src/filters/shared/user-defaults.ts` / `user-defaults.json` — override shared defaults
- `src/filters/shared/user-styles.ts` / `user-styles.json` — override shared styles

All of these are gitignored, so they stay local to your machine. Example files are included at [`user-defaults.example.ts`](src/filters/shared/user-defaults.example.ts) and [`user-styles.example.ts`](src/filters/shared/user-styles.example.ts). The Global Settings **Defaults** and **Styles** panels edit the `.json` overrides through the UI.

## Sounds

Filter rules use `.tts("Six Link")` to play a custom alert sound. There are two kinds of TTS sounds:

- **Manifest sounds** — defined in `src/sounds/manifest.ts`. These are the canonical sounds for shared filter sections (currency drops, flasks, links, etc.). Their filenames are derived from the `id` field (e.g. `chaos_orb.mp3`), while the spoken `text` can be changed independently without breaking existing filters.
- **Ad-hoc sounds** — any text string passed to `.tts("My Sound")` in a user filter config. The filename is derived from the text itself and is regenerated on export.

The TTS **locale** (a Google Translate language code such as `en-US` or `de-DE`) and **speed** (clamped to 0.5–2.0) are configured in Global Settings.

### Generating and syncing

From the UI, **Generate sounds** regenerates every manifest and ad-hoc MP3 and syncs the pack to your PoE folder; **Sync sounds** cleans stale files and copies the existing pack. The equivalent CLI commands are:

```bash
npm run generate-sounds   # regenerate all MP3s (uses the saved TTS settings)
npm run clean-tts         # remove unused .mp3 files from sounds/
npm run sync-sounds       # copy sounds/ to your PoE folder
```

### Sound pack folder

Exported filters reference a `poeft-sounds-{version}/` folder next to your `.filter` file so sounds don't collide with other tools. The export step copies the repo sounds there automatically and removes files that are no longer referenced.

The `{version}` comes from `SOUND_PACK_VERSION` in `src/sounds/paths.ts` — bump it there and every script, type, and test follows automatically.

```text
Path of Exile/
  Example.filter
  poeft-sounds-{version}/
    chaos_orb.mp3
    six_link.mp3
    ...
```

Override the folder name with the **Sounds Folder Name** setting in Global Settings.

## Settings

Settings live in `settings.json` at the repo root and are edited through the UI. On first run, existing `.env` values (`FILTER_PATH`, `SOUNDS_FOLDER`) and `.tts-settings.json` are migrated into `settings.json`; after migration there is no `.env` fallback.

## Generation

Generated files are refreshed automatically before export (`preexport`) and on install (`postinstall`). You can also run them manually:

```bash
npm run generate-types       # item type unions from BaseTypes.csv
npm run generate-sound-types # SoundFile union from local sounds/
```

These are autogenerated and gitignored — they never create commit churn from local-only changes.

## Notes

- Most config fields have autocomplete for Path of Exile item classes, base types and link patterns
- `soundFile("...")` also gets typed sound filename suggestions for literal filenames
- Custom filter folders under `src/filters/` are gitignored by default
- `src/assets/BaseTypes.csv` comes from the public FilterBlade assets repo and can be refreshed locally with `npm run update-basetypes`
- A GitHub Actions workflow at `.github/workflows/update-basetypes.yml` checks upstream weekly and opens a PR when the CSV changes
